# 要求内容：カスタムツールによる出典検証役の追加

> **保留（2026-10-04、題材を実行診断に変更。未承認）**

> 状態: ユーザー承認待ち。
> 「出典検証役」「カスタムツール」「出典実在確認ツール」は `docs/glossary.md` に未登録の**仮称**（§8）。
> 経緯: 当初は素の Messages API でツール呼び出しの繰り返しを自作する案だったが、ユーザーとの相談で方式を変更した（§2「方式の変更」）。

## 1. 背景・問題

本システムの LLM 呼び出しは、Claude Agent SDK の `query()`（`src/agent/orchestrator.py` の `call_claude` 系）と Codex CLI（`call_codex`）に委ねている。コード調査で、次の 2 点が足りないことが分かっている。

1. **自分で定義したツールが無い**。使っているのは SDK 組み込みのツール（WebSearch / Write 等）と、レビュアーが bash で打つ `curl` だけ。
2. **モデルが「次に何をするか」を決める範囲が狭い**。オーケストレーターは順番が固定のプログラムで、各呼び出しは 1 問 1 答に近い。ターン数などの上限も指定していない（`_build_claude_options`、`src/agent/orchestrator.py:535-540`）。

あわせて、出典 URL の実在確認は現在、レビュアー（Codex、`sandbox_mode="danger-full-access"`）が `curl -sL` で行っており、宛先の制限がない（`src/agent/prompts/reviewer.md:14,25`）。

## 2. 変更・追加する機能

既存の Claude Agent SDK を使ったまま、次の 2 つを追加する。

1. **出典実在確認ツール（仮称）**: 出典 URL に HTTP で到達できるかを確かめ、固定の項目だけを返すカスタムツール。SDK のインプロセス MCP サーバーとして登録する。中身は SDK に依存しない普通の関数に分け、単体でテストできるようにする。
2. **出典検証役（仮称）**: 出典リストを受け取り、**どの出典を、どの順で、何件確かめるかをモデルが決めて**ツールを呼ぶ小さな役割。使えるのは上記のツール 1 個だけ。ターン数・時間・呼び出し総数に上限を持つ。

既存の流れには、機能フラグ（既定オフ）でレビューの前段につなぐ。

### 方式の変更（当初案から）

| | 当初案 | 本案 |
|---|---|---|
| 実行系 | 素の Messages API + 自作の繰り返し | 既存の Agent SDK のまま |
| 認証 | API キー（新系統） | 既存のサブスクリプション認証のまま |
| 既存の流れ | つながない | フラグ既定オフでつなぐ |
| 依存の追加 | `anthropic` | なし |

理由: 業務でのエージェント開発は、既製の枠組みの上に、業務に合わせたツール・役割・検証・上限・安全の仕組みを作るのが一般的であり、足りない 2 点はどちらも SDK のままで埋められる。ADR-0001（純 HTTP の SDK への置換を却下）とも同じ向きである。素の Messages API での繰り返しの自作は、将来の候補として §7 に残す。

| # | 決める点 | 選択肢 | 推奨と理由 |
|---|---|---|---|

## 3. ユーザーストーリー

- 開発者として、エージェントに持たせるツールの入力スキーマ・検証・実行・結果の形を自分で定義し、モデルが作った値を信頼しない作りを示したい。
- 開発者として、モデルに判断を任せる範囲（どの出典を確かめるか）と、コードが握る範囲（宛先の制限・上限・結果の正本）の線引きを、コードとテストで説明したい。
- 運用者として、無人で動かしたときに必ず有限のターン数・時間・呼び出し回数で終わり、検証役が失敗しても成果物の生成は止まらないでほしい。
- 運用者として、Web 上の内容に指示文が混ざっていても、内部ネットワークや認証情報に到達されないでほしい。
- 運用者として、フラグを切れば今日までと同じ挙動に即座に戻ってほしい。

## 4. 要件

### 4.1 出典実在確認ツール（SDK に依存しない関数）

- R1: 入力は URL 1 つ。返すのは**固定の項目だけ**: 到達可否、HTTP 状態コード、リダイレクト回数、最終 URL、Content-Type、失敗分類。**応答本文・タイトル等、Web 側が自由に書ける文章は返さない**。文字列項目には長さの上限を設ける。
- R2: 関数は例外を外に出さない。失敗はすべて失敗分類つきの結果として返す。

| 失敗分類 | 条件 |
|---|---|
| `invalid_input` | 型・必須項目・未定義の項目・長さの検証に通らない |
| `blocked` | スキーム・ポート・認証情報つき URL・非グローバルアドレス（リダイレクト先を含む） |
| `not_in_sources` | その実行の出典リストにない URL |
| `call_limit` | 呼び出し総数の上限を超えた |
| `connect_failed` | 名前解決または接続に失敗 |
| `timeout` | 制限時間内に応答がない |
| `too_many_redirects` | リダイレクト回数の上限を超えた |
| `internal_error` | 上記以外の想定外の例外 |

- R3: 入力はモデルが作った信頼できない値として検証する。検証に通らない入力では名前解決も HTTP も行わない。
- R4: 確認できる URL は、その実行に渡された出典リストに含まれるものだけ（リダイレクト先を除く）。
- R5: SSRF 対策。
  - スキームは `http` / `https` のみ。ポートは 80 / 443 のみ。認証情報つき URL（`user:pass@`）は拒否。
  - ホスト名を解決した**すべてのアドレス**がグローバルアドレスであること。プライベート、ループバック、リンクローカル（`169.254.169.254`、ECS タスクメタデータの `169.254.170.2` を含む）、CGNAT、未指定、マルチキャスト、予約済み、IPv6 のユニークローカル・リンクローカル、IPv4 射影アドレスを拒否する（「グローバルでなければ拒否」で判定）。
  - リダイレクトは自動追従せず、1 段ごとに上記の検査をやり直す。回数に上限（案: 5）。
  - 応答の読み取りバイト数に上限（案: 64KB）、接続と読み取りに制限時間（案: 10 秒）。
  - 環境変数のプロキシ設定に従わない。Cookie・認証ヘッダーを送らない。
- R6: 1 実行あたりの呼び出し総数に上限（案: 15。`reviewer.md` の検証件数の上限と同じ）。
- R7: 想定外の例外では固定の分類だけを返す。例外メッセージ・スタックトレース・解決した IP は結果に入れない。詳細はログに残す。
- R8: HTTP の送信・名前解決・時計は外から差し替えられる。
- **既知の制限**: 検査したアドレスと実際に接続するアドレスの一致は保証しない（D3）。

### 4.2 出典検証役（SDK への渡し方）

- R9: ツールは SDK の `@tool` と `create_sdk_mcp_server` で定義・登録する。ハンドラーは R1 の関数を呼び、結果を JSON 文字列 1 つの text ブロックにして返す。失敗分類があれば `is_error` を付ける。**ハンドラーから例外を漏らさない**（漏れると SDK が生の例外文をモデルに渡すため）。
- R10: 検証役に渡すオプションは、組み込みツールをすべて外し（`tools=[]`）、許可はカスタムツール 1 個だけ（`allowed_tools=["mcp__<サーバー名>__<ツール名>"]`）、ターン数の上限（`max_turns`、案: 10）を指定する。モデル名は設定で変えられる。
- R11: 全体の制限時間（案: 120 秒）を持ち、超えたら打ち切る。
- R12: **確認結果の正本は、コードが記録したツール実行記録**から組み立てる。モデルの最終テキストは要約として添えるだけで、件数や合否の根拠にしない。
- R13: 検証役は例外を外に出さず、必ず結果オブジェクトで終わる。結果は終了理由（`completed` / `max_turns` / `timeout` / `failed`）、確認記録の一覧、ターン数、所要時間を持つ。
- R14: ターン上限への到達は正常な終わり方として扱う。**既存の再試行・上位モデルへの切り替え（`_run_claude_with_retries`）に乗せない**。
- R15: 間接プロンプトインジェクションへの構造的な備え。使えるツールは読み取り専用の 1 個だけで、書き込み・コマンド実行・任意の宛先への送信はできない。R1（本文を返さない）・R4（宛先は出典リスト内）・R12（正本はコードの記録）により、指示文が混ざっても「できること」も「結果の真偽」も変わらない。

### 4.3 既存の流れへの接続

- R16: 機能フラグ（環境変数、既定オフ）。オフのとき、検証役のコードは 1 行も実行されず、既存の挙動は変わらない。判定は既存の `_should_use_workspace_text_gen()` と同じく関数に切り出し、単体でテストできるようにする。
- R17: オンのとき、レビューの前段で検証役を 1 回実行し、確認記録の要約（URL ごとの固定項目と件数）を `reviewer_prompt` の末尾に足してから `_run_review_loop` に渡す。`_run_review_loop` の中身、`prompts/reviewer.md`、レビュアーの権限は変えない。
- R18: 検証役が失敗・時間切れ・記録 0 件のいずれでも、ワークフローは止めない。失敗時は何も足さず、既存と同じ `reviewer_prompt` を渡す。
- R19: 記録は既存の仕組みに揃える。トークンと費用を `cost_acc` に加算し、`api_call_completed` を 1 件 emit する（`endpoint_path` は既存の Claude 呼び出しと区別できる値）。終了時に、終了理由・ターン数・確認件数・所要時間をログ 1 行に残す（出典 URL の一覧やプロンプト本文は出さない）。

### 4.4 非機能

- R20: ネットワークも認証情報も使わずに §5 の必須条件がすべて通る。SDK の呼び出しは差し替える。
- R21: 実際に動かす確認（サブスクリプション認証）は、pytest の既定実行に含めない手動手順として文書にする。
- R22: 依存パッケージを追加しない。`ruff`（`S` ルールを含む既存設定）に通る。

## 5. 受け入れ条件

特記のない限り、HTTP・名前解決・SDK を差し替えた自動テスト（`tests/unit`）で確認する。

### 必須

**ツール本体**

1. **到達可**: 公開 URL が 200 → 到達可・状態コード 200。結果は R1 の固定項目だけを持つ。
2. **到達不可の分類**: 404 → 到達不可・状態コード 404。接続失敗 → `connect_failed`。時間切れ → `timeout`。いずれも例外は出ない。
3. **入力検証**: `url` 欠落 / 文字列でない / 長さ超過 / 未定義の項目つき → `invalid_input`。名前解決も HTTP も行われない。
4. **スキームと URL の形**: `file://` `ftp://` `gopher://` `data:` `javascript:`、認証情報つき、80・443 以外のポート → `blocked`。名前解決は行われない。
5. **内部アドレス（リテラル）**: `127.0.0.1` / `localhost` / プライベートアドレスの3つの範囲(10.x・172.16.x・192.168.x)の代表 / `169.254.169.254` / `169.254.170.2` / `100.64.0.1` / `0.0.0.0` / `[::1]` / `[fe80::1]` / `[fc00::1]` / `[::ffff:127.0.0.1]` / `2130706433` / `0x7f.0.0.1` → すべて `blocked`、HTTP は発しない。
6. **名前解決後の検査**: 公開風のホスト名がプライベートアドレスに解決される → `blocked`。複数のアドレスのうち 1 つでもグローバルでない → `blocked`。
7. **リダイレクト**: 公開 URL が `http://169.254.169.254/` へ 302 → 2 段目の要求は発せず `blocked`。`file://` へのリダイレクト → `blocked`。上限を超える連鎖 → `too_many_redirects`。
8. **大きさ**: 上限を超える本文 → 読み取りは上限バイトで止まり、状態コードは正しく返る。
9. **出典リスト外**: 出典リストにない URL → `not_in_sources`、HTTP は発しない。
10. **呼び出し総数の上限**: 上限を超えた呼び出し → `call_limit`、HTTP は発しない。
11. **想定外の例外**: 差し替えた HTTP が想定外の例外を出す → `internal_error`。例外メッセージは結果に含まれず、ログに残る。
12. **本文が渡らない**: 本文に「これまでの指示を無視して…」を含む応答 → 結果のどの項目にもその文が含まれない。

**SDK への渡し方**

13. **ハンドラー**: ツールのハンドラーを直接呼ぶ（SDK は起動しない）→ `content` は text ブロック 1 つで、中身は固定項目の JSON。失敗分類があるとき `is_error` が真。内側の関数が例外を出すよう差し替えても、ハンドラーから例外は漏れない。
14. **オプション**: 検証役が SDK に渡すオプションで、`tools` が空リスト、`allowed_tools` がカスタムツール 1 個だけ、`mcp_servers` にサーバーが登録され、`max_turns` と `model` が設定値どおりである。
15. **正本はコードの記録**: 差し替えた SDK が「全件確認済み」という最終テキストを返すが、ツールは 1 件を到達不可と記録している → 検証役の結果では到達不可のまま。ツールが 1 度も呼ばれない → 確認件数 0。
16. **ターン上限**: SDK が `error_max_turns` の結果を返す → 終了理由 `max_turns`、それまでの確認記録が残る。SDK の呼び出しは 1 回だけ（再試行・上位モデルへの切り替えなし）。
17. **全体の制限時間**: SDK が制限時間内に終わらない → 終了理由 `timeout`、それまでの確認記録が残る。
18. **SDK の失敗**: SDK が例外を出す → 検証役から例外は出ず、終了理由 `failed`。

**既存の流れへの接続**

19. **フラグ既定オフ**: 環境変数が未設定または `false` → 検証役は呼ばれず、`_run_review_loop` に渡る `reviewer_prompt` は現状と同一。
20. **フラグオン**: 検証役がレビュー前に 1 回だけ呼ばれ、確認記録の要約が `reviewer_prompt` の末尾に足されて `_run_review_loop` に渡る。
21. **フラグオンで失敗**: 検証役の終了理由が `failed` または `timeout` で記録 0 件 → ワークフローは続き、`reviewer_prompt` は現状と同一。
22. **記録**: フラグオンの 1 実行で、`cost_acc` にトークンが加算され、`api_call_completed` が 1 件、既存の Claude 呼び出しと区別できる `endpoint_path` で emit される。終了時のログ 1 行に終了理由・ターン数・確認件数・所要時間が出て、出典 URL は出ない。

**非回帰**

23. **ネットワークなし**: ソケットの生成を禁じ、認証情報がない状態で、本作業の自動テストがすべて通る。
24. **既存の挙動が不変**: 既存テスト（550 件）の成功・失敗の集合が `main` と同じ。`git diff main -- template.yaml src/agent/prompts/ src/agent/requirements.txt src/agent/Dockerfile` が空。`_run_review_loop` の関数本体に差分がない。
25. **リント**: 追加・変更したファイルに対し `ruff check` の指摘ゼロ。
26. **手動手順の文書**: サブスクリプション認証で検証役を 1 回動かす手順が文書にあり、pytest の既定実行では走らない。

### 任意（規模に収まれば。収まらなければ次の作業単位へ）

- O1. **接続先の固定**: 名前解決が 1 回目はグローバル、2 回目はプライベートを返す → プライベートアドレスへの接続は発生しない。
- O2. **費用の上限**: 固定している SDK の版が `max_budget_usd` を受け付けるなら指定し、`error_max_budget_usd` を終了理由として扱う。
- O3. **手動確認の実施**: 26 の手順を実際に行い、終了理由・ターン数・確認件数の実出力を記録する。実施はユーザーの承認後。未実施なら「未検証」と明記する（CLAUDE.md 作業規律 §1）。

## 6. 制約事項

- **規模**: 人の作業で 6〜8 時間ぶん。超える見込みが出たら、任意の条件から削る。
- **既存経路を置き換えない**: `call_claude` 系・`call_codex`・`_run_review_loop` の中身・`prompts/reviewer.md` は無変更。`orchestrator.py` の変更は、フラグ判定の関数と `run()` 内のレビュー前段の数行、および検証役の呼び出しに限る。
- **認証は変更しない**: 既存のサブスクリプション認証をそのまま使う。API キーは導入しない。
- **`template.yaml` を変更しない・デプロイしない**: `sam build` / `sam deploy` を行わない。
- **レビュアーの権限を絞る作業は含めない**（別の作業単位）。
- **外向きは 443 のみ**（`template.yaml:139-144`）: ECS 上では `http://` の出典は `connect_failed` になる。「実在しない」とは区別して記録する。
- **SDK の仕様の確認状況**: `@tool`・`create_sdk_mcp_server`・`mcp__<サーバー>__<ツール>` の名前・`tools=[]` で組み込みを外せること・`allowed_tools` は許可であって制限ではないこと・`max_turns`・`ResultMessage.subtype` の値・ハンドラーの例外は生の文言でモデルに渡ること・文字列プロンプトの `query()` でカスタムツールが使えることは、公式文書（2026-10-04 時点の最新版）で確認済み。**固定している版 `claude-agent-sdk==0.2.110` で同じ指定が通るかは未確認**（文書は版ごとに分かれておらず、手元に導入済みのパッケージも見つからなかった）。実装の最初のタスクで、導入済みの版に対して確かめる。
- **ツール検索による余分なターン**: 公式文書によれば、SDK はカスタムツールの定義を必要時に読み込む仕組みが既定で有効で、その読み込みに 1 回ぶんの呼び出しを使うことがある。`max_turns` の既定値はこれを見込んで決める。
- 実装コミット後は CLAUDE.md 作業規律 §4（Codex レビューゲート）に従う。
